# 어르신 디지털 안내 챗봇 — UI/UX 사전 분석 및 디자인 시안

## 1. 외부 사례 조사 (12건)

### 1. Peter (PeterAI)
- **유형:** 음성 기반 AI 어시스턴트 (iOS 전용)
- **대상:** 50세 이상 어르신
- **핵심 특징:** 화면 없이 음성으로만 대화. 복잡한 메뉴/아이콘 배제. 차분하고 느린 톤으로 답변. 매일 이메일 요약 제공.
- **참고 가치:** 음성 우선 UX의 극단적 단순화. "설명을 듣지 않아도 되는" UX의 정석.

### 2. ElderlAI
- **유형:** 대글씨 AI 동반자
- **대상:** 고령자
- **핵심 특징:** 큰 글자, 편지/서류 읽어주기, 사기 탐지, 리마인더. 무료 안전 도우미.
- **참고 가치:** "큰 글자"를 핵심 가치로 내세운 사례. 읽기 편한 레이아웃.

### 3. Sensely (Molly)
- **유형:** 아바타 기반 대화형 AI (의료)
- **대상:** 의료 서비스 이용자, 고령자
- **핵심 특징:** 친근한 아바타(Molly)가 대화. SMS/WhatsApp/웹 멀티채널. Mayo Clinic/NHS 기반 콘텐츠. 4/5 사용자가 아바타를 선호.
- **참고 가치:** 아바타가 신뢰감·친근감 부여. 텍스트만으로는 부족한 정서적 유대감 해결.

### 4. ElliQ (Intuition Robotics)
- **유형:** 하드웨어 동반 로봇
- **대상:** 65세 이상, 독거 어르신
- **핵심 특징:** 물리적 존재감. 먼저 말을 건네고 대화를 시작. 건강 리마인더, 인지 활동. 95% 사용자가 외로움 감소 보고. 무료 대여(미국 일부 주).
- **참고 가치:** "먼저 말을 거는" 주도적 UX. 수동적 대기 아닌 능동적 개입.

### 5. SeniorTalk
- **유형:** WhatsApp/SMS 기반 AI 동반자
- **대상:** 시니어, 요양시설
- **핵심 특징:** 앱 설치 불필요(기존 메신저 활용). 페르소나 선택 가능. 음성/텍스트 모두 지원. 사기 탐지. 요양시설 단체 도입.
- **참고 가치:** 기존 플랫폼 활용으로 진입장벽 제거. "다운로드하지 않아도 되는" UX.

### 6. MESA-Bot
- **유형:** 정신건강 지원 챗봇 (연구 기반)
- **대상:** 고령자
- **핵심 특징:** 고령자 28명과 공동설계(co-design). 큰 글씨·큰 버튼·최소 시각 정보 혼잡·간단한 문장 구조. 24/28 사용자가 "쉽다, 편하다" 평가.
- **참고 가치:** 고령자 직접 참여 설계의 결과. "간단하다"는 것이 최고의 UX.

### 7. UjaBienestar
- **유형:** 멀티모달 대화형 챗봇 (감정 지원)
- **대상:** 고령자
- **핵심 특징:** 음성+텍스트+비디오 멀티모달. 접근성·사용성·실현가능성 평가 완료. 감정적 지지 + 실용적 지원.
- **참고 가치:** 멀티모달 입력이 고령자에게 유리하다는 실증.

### 8. Florence
- **유형:** 메신저 기반 복약 리마인더 챗봇
- **대상:** 만성질환자, 고령자
- **핵심 특징:** Facebook Messenger에서 복약 알림, 약 정보, 병원/약국 찾기. 기존 메신저 활용.
- **참고 가치:** 단일 기능(복약)에 집중한 단순 UX. 메신저 통합.

### 9. Ada Health
- **유형:** AI 증상 체커 앱
- **대상:** 일반 사용자 (고령자 포함)
- **핵심 특징:** 4.8/5 평점. 5단계 질문으로 증상 평가. 신뢰감 있는 의료 콘텐츠. 가족 프로필 공유.
- **참고 가치:** 질문→답변 흐름의 직관성. 신뢰감을 주는 비주얼 디자인.

### 10. Buddy Agent
- **유형:** 접근성 강화 AI 동반자 (PWA)
- **대상:** 고령자
- **핵심 특징:** 고대비 모드(WCAG AAA) 토글. 따뜻한 호박색/깊은 검정 배경 전환. 1.35배 스케일러. 음성 상호작용.
- **참고 가치:** 고대비 테마 전환 기능. 사용자가 직접 선택하는 접근성.

### 11. Replika
- **유형:** 개인화 AI 대화 동반자
- **대상:** 일반 (고령자도 사용)
- **핵심 특징:** 상호작용을 통해 학습, 감정 인식, 게임/퀴즈로 인지 자극.
- **참고 가치:** 개인화된 대화가 지속적 사용 동기 부여.

### 12. VP0 Elderly-Friendly Template
- **유형:** 시니어 친화 UI 템플릿 가이드
- **핵심 원칙:** 큰 글자(Dynamic Type), 강한 대비, 큰 탭 영역, 단순한 네비게이션, 평이한 언어, 중요한 행동 확인.
- **참고 가치:** 체계적인 시니어 UI 설계 가이드라인.

## 2. UI/UX 분석 종합 (14개 항목 기준)

| 항목 | 조사 결과 공통 패턴 |
|---|---|
| 1. 글자 크기 | 최소 16px, 이상적 18~24px. 모바일 36~48pt 권장 |
| 2. 글자 대비 | WCAG AA(4.5:1) 이상, 이상적 WCAG AAA(7:1) |
| 3. 버튼 크기 | 최소 44x44px, 이상적 48x48px 이상 |
| 4. 버튼 간 간격 | 최소 8px, 이상적 16px 이상 |
| 5. 입력 방식 | 음성 우선 추천, 텍스트 입력은 큰 키보드/버튼 대체 |
| 6. 질문 예시 | 카드형/버튼형으로 배치, 클릭 한 번으로 선택 가능 |
| 7. 화면 정보량 | 최소화. 한 화면에 하나의 초점. |
| 8. 메뉴 구조 | 플랫(단일 레벨), 홈 버튼 항상 표시 |
| 9. 음성 사용 | 대다수 서비스가 음성 지원. 텍스트+음성 병행 권장 |
| 10. 답변 표시 | 대화형(채팅 버블), 아바타 제공 시 신뢰도 상승 |
| 11. 오류/안내 | 명확한 대체 경로 제공, 당황하지 않는 톤 |
| 12. 신뢰감 | 의료기관 로고, 전문 콘텐츠 인용, 아바타, 개인정보 투명성 |
| 13. 실수 방지 | 확인 대화상자, 단순 제스처, 되돌리기 버튼 |
| 14. 학습 불필요 | 첫 화면에서 모든 기능 노출, 설명 텍스트 최소화 |

## 3. 추가 기능 제안 3개

### 기능 1: 읽어주기 (Text-to-Speech)
1. **어르신에게 어떤 도움이 되는가:** 시력이 약한 어르신이 답변을 눈으로 읽지 않고 귀로 들을 수 있음
2. **실제 사용 상황:** "보이스피싱이 의심되면" 질문 후 답변이 길 때, 한 번 터치하면 전체 답변을 읽어줌
3. **추가할 수 있는 이유:** Web Speech API는 모든 최신 브라우저에서 지원, 별도 라이브러리 불필요
4. **예상 구현 난이도:** 낮음 (Web Speech API + 버튼 추가)
5. **UI:** 답변 영역 하단에 "듣기" 버튼 (큰 스피커 아이콘 + "듣기" 텍스트)

### 기능 2: 자주 묻는 질문 (FAQ)快捷
1. **어르신에게 어떤 도움이 되는가:** 매번 입력하지 않아도 자주 쓰는 질문을 한 번에 선택
2. **실제 사용 상황:** 첫 화면에 "인기 질문" 카드 3~4개 표시, 탭하면 바로 답변
3. **추가할 수 있는 이유:** 현재 eval.mjs의 QUESTIONS 배열에서 인기 질문 추출 가능, UI 카드 추가만으로 구현
4. **예상 구현 난이도:** 낮음 (기존 질문 데이터 활용 + UI 카드)
5. **UI:** 입력창 위에 "인기 질문" 섹션, 큰 카드형 버튼으로 표시

### 기능 3: 큰 글씨 모드 토글
1. **어르신에게 어떤 도움이 되는가:** 기본 글자 크기보다 더 크게 확대하는 토글
2. **실제 사용 상황:** 첫 방문 시 또는 화면이 작게 느껴질 때 상단의 "큰 글씨" 버튼 터치
3. **추가할 수 있는 이유:** CSS 클래스 하나로 전체 글자 크기 변환 가능 (font-size 스케일링)
4. **예상 구현 난이도:** 낮음 (CSS 클래스 토글 + localStorage로 설정 저장)
5. **UI:** 상단 상태 영역에 "큰 글씨" 토글 스위치

## 4. 현재 프로젝트 UI 분석

**현재 상태 (App.tsx):**
- 모든 스타일이 인라인 `style={{...}}`
- Vite 데모 CSS 잔존 (index.css, App.css)
- 색상 하드코딩 (#dcfce7, #fee2e2, #fafafa, #b45309)
- 카드형 구조 없음, 평면적 레이아웃
- 버튼 크기 작음, 간격 부족
- 정보 밀도 높음 (배지+출처+피드백+판정이 모두 하단에 집중)

**개선 방향:**
- 인라인 스타일 → 클래스 기반 CSS로 전환
- Vite 데모 CSS 제거, 실제 앱용 CSS 작성
- 색상 변수화 + light/dark 대응
- 카드형 레이아웃 도입
- 버튼 크기 확대 + 간격 확보
- 정보 계층 명확화 (헤더 → 입력 → 답변 → 보조 정보)
