# 어르신 디지털 안내 챗봇

로컬 RAG(Retrieval-Augmented Generation) 파이프라인으로 만든 "어르신 디지털·스마트폰 이용 안내" 챗봇입니다. 모두콘 메인퀘스트3(RAG 가이드 챗봇 만들기) 실습으로 제작했습니다.

## 서비스 소개
디지털배움터 이용 방법, 보이스피싱·스미싱 예방, 무인민원발급기·정부24 이용 등 어르신이 자주 궁금해하는 디지털 생활 질문에, 실제 공개 자료 15건에 근거해 쉬운 말로 답합니다. 자료에 없는 내용은 지어내지 않고, 근거가 약하면 조심스럽게 답하거나 범위 밖이면 정중히 거부합니다.

## 실행 전제 조건 (필수)
- Ollama 설치 및 실행 (`ollama serve`)
- 모델 2개: `ollama pull qwen3.5:2b` (답변 생성), `ollama pull embeddinggemma` (임베딩)
- Node.js 18 이상 (내장 fetch 사용)
- 브라우저에서 `http://localhost:11434`(Ollama API) 접근 가능해야 함 — 원격 서버 사용 시 SSH 포트포워딩(`-L 11434:localhost:11434`) 필요

## 실행 방법
1. `cd app`
2. `npm install`
3. `npm run dev`
4. 브라우저에서 http://localhost:5173 접속

## 아키텍처 (완전 무료 구성)
근거자료 15건(senior-docs.source.json) → Ollama embeddinggemma로 사전 임베딩(768차원, senior-docs.json) → 브라우저에서 하이브리드 검색(코사인 유사도 + BM25 + RRF 융합) → 프롬프트 조립 → Ollama qwen3.5:2b로 스트리밍 답변 → LLM-as-a-Judge 자동판정 → 사람 피드백(👍👎)

임베딩·검색은 브라우저/로컬에서, 답변 생성은 로컬 Ollama에서 처리하며, 배포는 GitHub Pages 정적 호스팅을 사용해 서버 비용이 전혀 들지 않습니다.

## 근거 자료 (15건)
- 디지털배움터 소개·운영주체·교육대상·비용·장소·스마트폰/키오스크 교육·AI안전교육·방문교육·신청문의·부처문의처·수준별과정 (SD-001~SD-011)
- 보이스피싱 예방, 스미싱·문자사기 예방, 무인민원발급기 사용, 정부24 온라인 발급 (SD-012~SD-015)

## 임계값 설계
- `THRESHOLD = 0.33`: 최고 코사인 유사도가 이보다 낮으면 "근거가 약합니다" 경고를 붙여 조심스럽게 답변
- `REFUSE = 0.30`: 이보다 낮으면 LLM을 아예 호출하지 않고 즉시 정중히 거부 (환각·엉뚱한 답변 원천 차단)
- `BM25_MIN = 2.0`: BM25 키워드 매칭이 이 값 이상으로 강하면, 코사인이 낮더라도 weak/refuse 판정을 해제 — 임계값을 낮추는 대신 신호(척도) 자체를 하이브리드로 강화하는 방향으로 설계

## 실험 기록
1. **브라우저 WASM 임베딩 → Ollama 로컬 임베딩 전환**: 초기 계획은 transformers.js로 브라우저에서 직접 임베딩하는 것이었으나, 실습 환경 네트워크에서 관련 CDN·모델 호스트가 차단되어 Ollama embeddinggemma로 아키텍처를 전환함. "로컬에서 무료로" 라는 취지는 그대로 유지됨.
2. **임베딩 접두어 실험**: `title:`/`task:` 접두어를 붙이면 오히려 임베딩 분리도가 떨어짐을 확인(compare_prefix.mjs). 접두어 없이 원문 그대로 임베딩하도록 최종 결정.
3. **BM25 하이브리드 검색 도입**: "스미싱 문자 오면 어떻게 해요?" 질문에서 코사인 유사도는 낮았지만(0.31) BM25 키워드 매칭은 강했던(2.10) 사례를 발견. 임계값을 낮추는 대신 BM25_MIN 가드를 추가해 신호 자체를 보강.
4. **한국어 전용 출력 강제**: qwen3.5:2b(중국계 베이스 모델)가 한자·중국어를 섞어 답하는 문제를 시스템 프롬프트에 "반드시 한국어로만" 규칙을 명시해 해결.
5. **LLM-as-a-Judge 평가**: 평가 질문 15개(도메인내 10 / 애매 2 / 도메인밖 3)를 eval.mjs로 일괄 실행한 결과 평균 87/100. 도메인밖 질문은 refusal 처리 정상 확인.
6. **judge 자기모순 관찰**: "교육비가 드나요?" 답변에서 score=100인데 noHalluc=false로 나온 사례 발견. 원본 자료와 대조한 결과 실제 환각은 아니었고(언급된 내용이 실제 SD-002에 존재), 문장별 인용 표시 누락과 qwen3.5:2b(2B, 소형 모델)의 채점 필드 간 자기일관성 부족이 원인으로 추정됨.

## 알려진 한계
- qwen3.5:2b는 2B 소형 모델이라 LLM-as-a-Judge의 6개 판정 필드 간 일관성이 완벽하지 않을 수 있음(점수와 개별 boolean 판정이 어긋나는 사례 존재)
- 답변이 문장마다 [ID] 인용 표시를 완벽히 달지 못하는 경우가 있음 (내용 자체는 근거자료 안에 있는 경우가 대부분)

## 평가 결과 재현
`node eval.mjs` 실행 — 같은 폴더에 `eval-results.json`으로 15개 질문 전체의 검색·답변·판정 결과가 저장됩니다.
