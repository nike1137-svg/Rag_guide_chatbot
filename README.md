# 이음이 — 어르신 디지털 안내 챗봇

로컬 RAG(Retrieval-Augmented Generation) 파이프라인으로 만든 "어르신 디지털·스마트폰 이용 안내" 챗봇입니다. 모두콘 메인퀘스트3(내 도메인에서 더 잘 대답해주는 RAG 챗봇 만들기) 과제로 제작했습니다.

- 배포 주소: https://nike1137-svg.github.io/Rag_guide_chatbot/
- 관련 문서: [PRD.md](./PRD.md) · [HANDOFF.md](./HANDOFF.md)

## 서비스 소개

디지털배움터 이용 방법, 보이스피싱·스미싱 예방, 무인민원발급기·정부24 이용 등 어르신이 자주 궁금해하는 디지털 생활 질문에, 실제 공개 자료 15건에 근거해 쉬운 말로 답합니다. 자료에 없는 내용은 지어내지 않고, 근거가 약하면 조심스럽게 답하거나 범위 밖이면 정중히 거절합니다.

답변마다 근거가 된 원문 조각의 ID·섹션·검색 방법·유사도를 칩으로 보여 주고, 칩을 누르면 원문 조각을 그대로 확인할 수 있습니다.

## 사용 전 준비 (중요)

이 앱은 **정적 페이지**입니다. 서버가 답변을 대신 만들지 않고, **페이지를 연 사용자의 브라우저가 그 컴퓨터의 Ollama를 직접 호출**합니다. 따라서 접속하는 분의 컴퓨터에 Ollama가 실행 중이어야 합니다.

### 1. 브라우저

Chrome 또는 Edge를 사용하세요. Safari는 https 페이지에서 로컬 Ollama 호출을 차단합니다. Chrome이 "로컬 네트워크 접근"을 물으면 허용을 누릅니다.

### 2. Ollama 실행과 모델 준비

```
ollama serve
ollama pull qwen3.5:2b
ollama pull embeddinggemma
```

### 3. GitHub Pages 주소에서 열 때 — CORS 허용

배포 주소(`https://nike1137-svg.github.io`)에서 로컬 Ollama를 호출하려면 Ollama 쪽에서 그 출처를 허용해야 합니다. 운영체제마다 한 번만 설정하고 **Ollama를 재시작**합니다.

**macOS**
```
launchctl setenv OLLAMA_ORIGINS "https://*.github.io"
```
설정 후 메뉴 막대의 Ollama 앱을 종료하고 다시 실행합니다.

**Windows**
```
setx OLLAMA_ORIGINS "https://*.github.io"
```
설정 후 작업 표시줄에서 Ollama를 종료하고 다시 실행합니다.

**Linux (systemd)**
```
sudo systemctl set-environment OLLAMA_ORIGINS="https://*.github.io"
sudo systemctl restart ollama
```

연결에 실패하면 화면 상단에 "로컬 모델 미연결" 배너와 위 명령이 그대로 표시되고, **다시 확인** 버튼으로 재시도할 수 있습니다. 페이지 오류와 실행 환경 문제를 구분할 수 있게 하기 위한 장치입니다.

## 아키텍처

근거자료 15건(`senior-docs.source.json`) → Ollama `embeddinggemma`로 사전 임베딩(768차원, `senior-docs.json`) → 브라우저에서 하이브리드 검색(코사인 + BM25 + RRF) → 프롬프트 조립 → 로컬 Ollama `qwen3.5:2b`로 스트리밍 답변(temperature 0.3) → LLM-as-a-Judge 자동판정 → 사람 피드백

검색 계산은 브라우저에서, 질문 임베딩과 답변 생성은 로컬 Ollama에서 처리하며, 배포는 GitHub Pages 정적 호스팅을 사용해 서버 비용이 들지 않습니다.

검색은 로컬 임베딩 1회 호출로 수십 ms 안에 끝나고 곧바로 답변 스트리밍이 이어지므로, '검색 중/답변 생성 중'을 구분하지 않고 하나의 진행 표시로 처리합니다.

### 청크 스키마

| 필드 | 뜻 | 예 |
|---|---|---|
| `id` | 근거를 가리키는 고정 이름 | `SD-004` |
| `text` | 사실 단위 본문(최소 121자, 평균 148자) | 교육 비용을 설명하는 문단 |
| `url` | 원문을 확인할 공개 주소 | 디지털배움터 공개 페이지 |
| `section` | 원문 안의 맥락 | `교육 비용` |
| `vector` | 검색용 768차원 임베딩 | embeddinggemma 출력 |

## 근거 자료 (15건)

- 디지털배움터 소개·운영주체·교육대상·비용·장소·스마트폰/키오스크 교육·AI안전교육·방문교육·신청문의·부처문의처·수준별과정 (SD-001~SD-011)
- 보이스피싱 예방, 스미싱·문자사기 예방, 무인민원발급기 사용, 정부24 온라인 발급 (SD-012~SD-015)

## 임계값 설계

| 상수 | 값 | 역할 |
|---|---|---|
| `THRESHOLD` | 0.33 | 최고 코사인 유사도가 이보다 낮으면 "근거가 약합니다" 경고 + 조심스러운 말투 |
| `REFUSE` | 0.30 | 이보다 낮으면 LLM을 호출하지 않고 즉시 정중히 거절 |
| `BM25_MIN` | 6.0 | BM25 강매칭이면 코사인이 낮아도 weak/refuse 해제 |

임계값을 낮추는 대신 **신호(척도) 자체를 하이브리드로 강화**하는 방향으로 설계했습니다. BM25_MIN은 최초 2.0에서 실측 후 6.0으로 상향했습니다(실험 7 참고).

## 평가 루브릭

고정 질문 세트 30개(도메인내 20 / 애매 4 / 도메인밖 6)를 `eval.mjs`로 일괄 실행하고 LLM-as-a-Judge 6필드로 채점합니다.

| 지표 | 측정 방법 | 목표값 | 현재 값 |
|---|---|---|---|
| 종합 점수 | 30문항 judge score 평균 | 80 이상 | **85.6** |
| 도메인내 품질 | `in` 20문항 평균 | 80 이상 | **88.8** |
| 애매 질문 품질 | `ambiguous` 4문항 평균 | 70 이상 | **93.0** |
| 도메인밖 거절 | `out` 6문항의 `refusal:true` 비율 | 100% | **100% (6/6)** |
| 검색 정합 | 도메인내 오탐 0 · 도메인밖 누락 0 | 0건 | **0건** |
| 출처 표시 | `cited:true` 비율 | 높을수록 좋음 | 0.63~0.70 (변동) |

`out` 6문항은 모두 `refuse=True`(maxCos 0.17~0.26)로 LLM 호출 없이 거절되었고, judge도 6문항 모두 `refusal:true`로 판정했습니다.

## 실패 사례와 원인 단계

점수만 남기지 않고, 어긋난 답변이 **검색·생성·판정 중 어느 단계에서 비롯됐는지** 정리했습니다.

| 사례 | 관찰된 값 | 원인 단계 | 판단 |
|---|---|---|---|
| "손주 생일 선물로 뭐가 좋을까요?" 등 도메인밖 2문항이 50점 | `refusal:true`인데 score 50 | **판정** | 정당한 거절인데 judge가 낮은 점수를 줌. 거절 동작 자체는 정상(6/6) |
| `noHalluc:false`가 30문항 중 18건 | 대부분 score 80~100과 동시 발생 | **판정** | 원문 대조 결과 실제 환각 아님. 2B judge의 필드 간 자기일관성 부족 (실험 6·13) |
| "과학기술정보통신부에도 문의 가능?" 75점 | `cited:false`, `noHalluc:false` | **생성** | 문장별 `[ID]` 표시 누락. 내용 자체는 SD-010 안에 존재 |
| `cited:false` 다수 | 프롬프트 강화 실험에서도 개선되지 않음 | **생성** | 2B 모델이 모든 문장에 인용을 붙이지 못함 |
| 도메인밖 질문이 BM25 우연 매칭으로 통과 (수정 전) | 코스피 3.71 / 드라마 4.40 | **검색** | BM25_MIN 2.0 → 6.0으로 수정 완료 (실험 7) |

정리하면 남은 실패는 대부분 **판정 단계의 편향**과 **생성 단계의 인용 누락**이며, 검색 단계의 실패는 실험 7에서 해소되었습니다.

## 알려진 한계

- `qwen3.5:2b`는 2B 소형 모델이라 LLM-as-a-Judge 6필드 간 일관성이 완전하지 않습니다. 답변 모델과 판정 모델이 같으므로 **독립 심사가 아니며**, 교육용 거친 신호로 읽어야 합니다.
- 답변이 문장마다 `[ID]` 인용을 완벽히 달지 못하는 경우가 있습니다(내용 자체는 근거자료 안에 있는 경우가 대부분).
- 간헐적으로 중국어·한자가 섞여 나오는 경우가 남아 있습니다.
- **음성 입력은 완전한 로컬 처리가 아닙니다.** Chrome의 Web Speech API는 음성을 Google 서버로 보내 인식하므로 인터넷 연결이 필요하고, Firefox에서는 동작하지 않습니다. 답변 읽어주기(TTS)는 브라우저 내장 기능으로 로컬에서 동작합니다.
- 검색·생성·판정은 모두 무료(로컬 Ollama)로 동작합니다. 실험 13의 Gemini judge만 외부 API를 사용했고, 무료 티어 범위에서 실행했습니다.

## 평가 결과 재현

```
node eval.mjs
```

같은 폴더에 `eval-results.json`으로 30개 질문 전체의 검색·답변·판정 결과가 저장됩니다. 현행 설정 기준(THRESHOLD 0.33, BM25_MIN 6.0, temperature 0.3) 평균 85.6점입니다. 답변 생성에 비결정성이 있어 실행마다 점수가 소폭 달라질 수 있습니다.
