# 이음이 — 어르신 디지털 안내 챗봇

로컬 RAG 파이프라인으로 만든 "어르신 디지털·스마트폰 이용 안내" 챗봇입니다.
메인퀘스트3(내 도메인에서 더 잘 대답해주는 RAG 챗봇 만들기) 과제로 만들었습니다.

- 배포 주소: https://nike1137-svg.github.io/Rag_guide_chatbot/
- 관련 문서: [PRD.md](./PRD.md) · [HANDOFF.md](./HANDOFF.md)

## 서비스 소개

디지털배움터 이용 방법, 보이스피싱·스미싱 예방, 무인민원발급기·정부24 이용처럼
어르신이 자주 궁금해하는 질문에 공개 자료 15건에 근거해 답합니다.

자료에 없는 내용은 지어내지 않습니다. 근거가 약하면 조심스럽게 답하고, 범위 밖이면 거절합니다.
답변 아래에는 근거가 된 조각의 ID·섹션·검색 방법·유사도가 칩으로 붙고, 칩을 누르면 원문 조각이 그대로 나옵니다.

## 사용 전 준비

이 앱은 정적 페이지입니다. 서버가 답변을 만들어 주지 않고, 페이지를 연 사람의 브라우저가
그 컴퓨터의 Ollama를 직접 호출합니다. 그래서 접속하는 쪽에 Ollama가 켜져 있어야 합니다.

### 1. 브라우저

Chrome이나 Edge를 쓰세요. Safari는 https 페이지에서 로컬 Ollama 호출을 막습니다.
Chrome이 "로컬 네트워크 접근"을 물으면 허용을 누릅니다.

### 2. Ollama 실행과 모델 준비

```
ollama serve
ollama pull qwen3.5:2b
ollama pull embeddinggemma
```

### 3. 배포 주소에서 열 때는 CORS 허용이 필요합니다

배포 주소에서 로컬 Ollama를 부르려면 Ollama 쪽에서 그 출처를 열어 줘야 합니다.
운영체제마다 한 번만 설정하고 Ollama를 재시작하면 됩니다.

macOS — 설정 후 메뉴 막대의 Ollama를 종료했다가 다시 실행합니다.
```
launchctl setenv OLLAMA_ORIGINS "https://*.github.io"
```

Windows — 설정 후 작업 표시줄에서 Ollama를 종료했다가 다시 실행합니다.
```
setx OLLAMA_ORIGINS "https://*.github.io"
```

Linux (systemd)
```
sudo systemctl set-environment OLLAMA_ORIGINS="https://*.github.io"
sudo systemctl restart ollama
```

연결이 안 되면 화면에 "로컬 모델 미연결" 배너가 뜨고 위 명령이 그대로 나옵니다.
복사 버튼과 "다시 확인" 버튼도 함께 있습니다. 페이지가 고장 난 것인지 내 컴퓨터 설정 문제인지
사용자가 구분할 수 있어야 해서 넣었습니다.

## 로컬에서 실행하기

```
cd app
npm install
npm run dev
```

http://localhost:5173/Rag_guide_chatbot/ 로 접속합니다. Node.js 18 이상이 필요합니다(내장 fetch 사용).
배포 갱신은 `npm run deploy`입니다.

## 화면에서 할 수 있는 것

- 연결 상태 칩과 미연결 배너 — Ollama 연결·모델 보유 여부를 표시하고, 실패하면 복구 명령과 재시도 버튼을 보여 줍니다
- 스트리밍 답변과 중지 — 토큰이 오는 대로 표시하고, 중지 버튼으로 생성을 끊을 수 있습니다
- 답변 안의 `[SD-000]` 인용 표시 — 지우지 않고 그대로 둡니다
- 출처 칩 — ID, 섹션, 검색 방법(의미 / 낱말 / 의미+낱말), 코사인 유사도를 함께 보여 줍니다
- 근거 원문 모달 — 칩을 누르면 원문 조각과 코사인·BM25 점수, 원문 링크가 나옵니다
- 약한 근거 경고 — 최고 유사도가 임계값 아래면 경고 배지가 붙고 말투가 조심스러워집니다
- 자동판정과 사람 피드백 — judge 6필드 결과와 좋아요/아쉬워요를 같은 화면에서 봅니다
- 접근성 — 큰 글씨, 고대비, 음성 입력, 답변 읽어주기

## 아키텍처

근거자료 15건(`senior-docs.source.json`)을 Ollama embeddinggemma로 미리 임베딩해
768차원 벡터스토어(`senior-docs.json`)로 만들어 둡니다. 질문이 들어오면 브라우저에서
코사인 + BM25 + RRF로 검색하고, 프롬프트를 조립해 로컬 qwen3.5:2b가 스트리밍으로 답합니다.
그 뒤에 LLM-as-a-Judge 자동판정과 사람 피드백이 붙습니다.

검색 계산은 브라우저에서, 질문 임베딩과 답변 생성은 로컬 Ollama에서 합니다.
배포는 GitHub Pages 정적 호스팅이라 서버 비용이 들지 않습니다.

검색은 임베딩 한 번 호출로 수십 ms 안에 끝나고 곧바로 답변 스트리밍이 이어집니다.
체감상 구분이 안 되기 때문에 '검색 중'과 '답변 생성 중'을 나누지 않고 하나의 진행 표시로 처리했습니다.

### 청크 스키마

`id`(SD-000 연속 부여) · `text`(사실 단위 본문) · `url`(원문 주소) · `section`(원문 안의 맥락) · `vector`(768차원).
본문만 남기지 않고 출처와 섹션을 함께 보관해야 답변에서 원문까지 되짚을 수 있습니다.
현재 15건이고, 가장 짧은 청크가 121자, 평균 148자입니다.

## 근거 자료 (15건)

- 디지털배움터 소개·운영주체·교육대상·비용·장소·스마트폰/키오스크 교육·AI안전교육·방문교육·신청문의·부처문의처·수준별과정 (SD-001~SD-011)
- 보이스피싱 예방, 스미싱·문자사기 예방, 무인민원발급기 사용, 정부24 온라인 발급 (SD-012~SD-015)

## 임계값 설계

- `THRESHOLD = 0.33` — 최고 코사인 유사도가 이보다 낮으면 "근거가 약합니다" 경고를 붙이고 조심스럽게 답합니다
- `REFUSE = 0.30` — 이보다 낮으면 LLM을 아예 호출하지 않고 거절합니다
- `BM25_MIN = 6.0` — BM25 키워드 매칭이 이만큼 강하면 코사인이 낮아도 weak/refuse를 풀어 줍니다

임계값을 낮추는 대신 신호 자체를 하이브리드로 보강하는 쪽을 택했습니다.
BM25_MIN은 처음 2.0이었는데 실측 후 6.0으로 올렸습니다(아래 실험 7).

## 루브릭과 지금 값

고정 질문 30개(도메인내 20 / 애매 4 / 도메인밖 6)를 `eval.mjs`로 돌리고 judge 6필드로 채점합니다.

- 종합 점수 — 목표 80 이상, 지금 85.6
- 도메인내 20문항 — 목표 80 이상, 지금 88.8
- 애매 4문항 — 목표 70 이상, 지금 93.0
- 도메인밖 거절률 — 목표 100%, 지금 6/6
- 검색 정합(도메인내 오탐·도메인밖 누락) — 목표 0건, 지금 0건
- 출처 표시(cited) — 지금 0.63~0.70, 실행마다 흔들립니다

도메인밖 6문항은 전부 maxCos 0.17~0.26으로 LLM 호출 없이 거절됐고, judge도 6문항 모두 refusal로 봤습니다.

## 실험 기록

"한 바퀴에 변수 하나" 규칙으로 돌렸습니다. 원본 스크립트는 두고 사본으로 실행한 뒤 산출물을 커밋했습니다.

1. **브라우저 WASM 임베딩 → Ollama 로컬 임베딩** — 처음엔 transformers.js로 브라우저에서 직접 임베딩할 계획이었는데, 실습 환경 네트워크에서 CDN·모델 호스트가 차단되어 Ollama embeddinggemma로 바꿨습니다. "로컬에서 무료로"라는 취지는 그대로입니다.
2. **임베딩 접두어** — `title:`/`task:` 접두어를 붙이면 오히려 분리도가 떨어졌습니다(compare_prefix.mjs). 접두어 없이 원문 그대로 임베딩합니다.
3. **BM25 하이브리드 도입** — "스미싱 문자 오면 어떻게 해요?"에서 코사인은 0.31로 낮은데 BM25는 2.10으로 강했습니다. 임계값을 내리는 대신 BM25_MIN 가드를 넣었습니다.
4. **한국어 전용 강제** — qwen3.5:2b가 한자·중국어를 섞어 답하길래 시스템 프롬프트에 "반드시 한국어로만"을 명시했습니다.
5. **첫 30문항 평가** — 평균 82. 기준선을 잡았습니다.
6. **judge 자기모순 관찰** — "교육비가 드나요?" 답변이 score 100인데 noHalluc은 false로 나왔습니다. 원본과 대조해 보니 실제 환각은 아니었고, 인용 표시 누락과 2B 모델의 필드 간 자기일관성 부족으로 보입니다.
7. **BM25_MIN 취약점** — eval 결과의 코사인 분포를 보니 도메인 밖 질문("코스피 지수", "드라마 추천")이 낮은 코사인(0.19~0.22)인데도 우연한 글자 겹침으로 BM25가 2.0을 넘어 거절을 우회하고 있었습니다. 진짜 매칭인 스미싱은 8.25, 우연 매칭인 코스피는 3.71, 드라마는 4.40이었습니다. BM25_MIN을 6.0으로 올려 30문항 재검증을 통과했습니다.
8. **THRESHOLD 0.40 A/B** — 임계값만 0.40으로 올려 재실행했더니 판정 변화가 0건이었습니다. 지금 질문 세트에 maxCos가 0.33~0.40 구간에 걸린 문항이 없기 때문입니다. 문항별 점수 변화는 답변 생성 비결정성 노이즈로 보고 0.33을 유지했습니다.
9. **top-k (5/10/20)** — 평균 75 / 80 / 83. K_VEC=5는 정답 출처가 누락되면서 애매 문항이 54점으로 떨어져 배제했습니다. 20은 소폭 개선이지만 노이즈 수준이라 10을 유지했습니다.
10. **프롬프트 강화** — 인용 규칙과 한국어 규칙을 강화했더니 평균은 80→86으로 올랐는데 cited 지표는 0.70→0.63으로 떨어졌습니다. 과제 기준인 '출처 표시'와 상충할 여지가 있어 채택을 보류했습니다.
11. **temperature (기본/0.3/0.7)** — 80 / 85 / 82. 낮은 온도가 일관되게 유리했고, 0.3이 판정 변동 문항이 가장 적어(8/30) 0.3을 채택했습니다.
12. **모델 크기 (0.8b/2b/4b)** — 0.8b는 60점(cited 0.30)으로 부적합했습니다. 4b는 GPU 없는 14GB 데스크탑에서 실행 중 gnome-shell이 재시작되는 디스플레이 크래시가 나서 수행 불가로 판정하고 `ollama stop`으로 복구했습니다. 2b를 유지합니다.
13. **judge 이중화** — 로컬 qwen3.5:2b와 Gemini 3.1 Flash-Lite(무료 티어)로 같은 30문항을 채점했습니다. 로컬 86 vs Gemini 92, 점수차 6점 이내가 50%, 플래그 4종 일치율이 71%였습니다. 로컬 judge가 "조심스러운 표현"을 환각으로 과판정하는 편향을 실측했습니다. 로컬 judge를 유지합니다. 키는 커밋에 넣지 않고 스크립트가 `~/.config/gemini/api.key`에서 읽습니다.

## 실패 사례와 원인 단계

점수만 남기면 다음에 무엇을 고칠지 알 수 없어서, 어긋난 답변이 검색·생성·판정 중 어디에서 비롯됐는지 나눠 적었습니다.

| 사례 | 관찰된 값 | 원인 단계 |
|---|---|---|
| 도메인밖 2문항이 50점 ("손주 생일 선물", "고혈압에 좋은 음식") | refusal은 true인데 score 50 | 판정 — 정당한 거절인데 judge가 점수를 깎음. 거절 동작 자체는 6/6 정상 |
| noHalluc이 false인 문항 18건 | 대부분 score 80~100과 함께 나옴 | 판정 — 원문 대조 결과 실제 환각 아님. 2B judge의 편향 |
| "과학기술정보통신부에도 문의 가능?" 75점 | cited·noHalluc 모두 false | 생성 — 문장별 [ID] 누락. 내용은 SD-010 안에 있음 |
| cited false가 여럿 | 프롬프트 강화 실험에서도 개선 안 됨 | 생성 — 2B 모델이 모든 문장에 인용을 붙이지 못함 |
| 도메인밖이 BM25 우연 매칭으로 통과 (수정 전) | 코스피 3.71 / 드라마 4.40 | 검색 — BM25_MIN 2.0→6.0으로 해결 |

남은 실패는 대부분 판정 단계의 편향과 생성 단계의 인용 누락입니다. 검색 단계 실패는 실험 7에서 없앴습니다.

## 알려진 한계

qwen3.5:2b는 2B 소형 모델이라 judge 6필드가 서로 어긋나는 경우가 있습니다. 답변 모델과 판정 모델이 같아서
독립 심사가 아니고, 교육용 거친 신호로 읽어야 합니다.

답변이 문장마다 [ID]를 완벽히 달지는 못합니다. 내용 자체는 근거자료 안에 있는 경우가 대부분입니다.
간헐적으로 중국어·한자가 섞이는 것도 남아 있습니다.

음성 입력은 완전한 로컬 처리가 아닙니다. Chrome의 Web Speech API는 음성을 Google 서버로 보내
인식하기 때문에 인터넷 연결이 필요하고 Firefox에서는 동작하지 않습니다.
답변 읽어주기는 브라우저 내장 기능이라 로컬에서 돌아갑니다.

검색·생성·판정은 전부 로컬 Ollama로 무료입니다. 실험 13의 Gemini judge만 외부 API를 썼고 무료 티어 안에서 돌렸습니다.

## 평가 재현

```
node eval.mjs
```

같은 폴더에 `eval-results.json`으로 30문항 전체의 검색·답변·판정 결과가 저장됩니다.
현재 설정(THRESHOLD 0.33, BM25_MIN 6.0, temperature 0.3) 기준 평균 85.6점입니다.
답변 생성에 비결정성이 있어 실행마다 점수가 조금씩 달라집니다.
